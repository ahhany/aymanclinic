# Decision Log

Format: ID · date · decision · rationale. Settled decisions are never edited — supersede with a new entry referencing the old one.

- **D1 · 2026-11-06 · Web app delivered as PWA, not a native tablet app.** One codebase serves tablet (home-screen installed, fullscreen, camera, offline shell), laptop, and reception PC; instant updates; no app-store overhead. Native wrapping remains possible later without data migration. UI is tablet-first (12–14″ landscape, keyboard + stylus).
- **D2 · 2026-11-06 · Hybrid layout.** Paper sections, order, and colours preserved, as collapsible interactive sections — not an exact page replica, not generic tabs. (Carried over from the ChatGPT discussion; to be confirmed by Dr. Ayman on first screens — see open-questions Q2.)
- **D3 · 2026-11-06 · Episode-centric data model.** Patient → Episodes (pregnancy / GYN problem / ICSI cycle) → Visits → Lab Reports → Lab Results → Prescriptions. A patient is not a pregnancy is not a lab result. Enables research exports without re-engineering.
- **D4 · 2026-11-06 · No Lovable (or any prototyping tool) in the build path.** The agent develops and tests the whole system in this workspace; the repo `github.com/ahhany/aymanclinic` (verified existing and empty) is the single source of truth. Deployment target decided later by Ahmed.
- **D5 · 2026-11-06 · Front end: Vite + React + TypeScript + Tailwind + shadcn/ui; PWA via vite-plugin-pwa.** Supersedes the Rev-1 Next.js choice. This is Lovable.dev's exact native stack, keeping the "import into Lovable later" option open while deploying equally well to Vercel/Netlify/Cloudflare/self-host. No Next.js-only constructs allowed.
- **D6 · 2026-11-06 · Data layer: Prisma ORM behind a repository interface; SQLite for dev/test, Supabase Postgres for production.** No Docker on the dev machine, so local Postgres/Supabase is impractical; SQLite is zero-install and fully local. Portability rules: no Postgres-only column types, JSON as text, UUIDs as strings. Production DB lives in Dr. Ayman's own Supabase project — he owns the data.
- **D7 · 2026-11-06 · Structured fields first, free text preserved.** Anything ever likely to be counted/filtered (Hb, BP, weight, diagnoses, drugs) is a typed field; narrative stays free text.
- **D8 · 2026-11-06 · "Additional tests" = a test_definitions dictionary.** Adding a test is a data row, never a schema migration. Each result stores its own unit and reference range.
- **D9 · 2026-11-06 · AI proposes, the doctor disposes.** All AI extraction passes a Review & Confirm screen; unclear values are left blank, never guessed; every result carries a verification status.
- **D10 · 2026-11-06 · Unit normalization at query time.** e.g. g/L → g/dL for Hb; unknown units are flagged for review, never assumed. (From the ChatGPT discussion's export design; adopted.)
- **D11 · 2026-11-06 · Research exports anonymized by default.** Identity (name/phone/address) lives in a restricted table separate from clinical data; exports use anonymous codes; beware indirect identifiers (exact dates + rare outcomes).
- **D12 · 2026-11-06 · Offline scope: v1 = online-first** with local draft autosave + connection indicator. Full offline sync with conflict resolution is Phase-2 hardening, explicitly not MVP.
- **D13 · 2026-11-06 · Bilingual labels mirroring the paper** (English medical terms, Arabic section headers where the paper has them); i18n structure from day 1 so a full Arabic UI can be added without rework.
- **D14 · 2026-11-06 · Patient code: single clinic-wide sequential code** (e.g. AYC-000125) assigned at registration; module membership (OBS/GYN/ICSI) shown as chips derived from episodes. Anonymous research IDs generated per export, never reused as identity.
- **D15 · 2026-11-06 · AI provider env-configured behind one interface, disabled by default.** No PHI to any AI API until a data-processing agreement and Egyptian Law 151/2020 legal review are in place.
- **D16 · 2026-11-06 · Testing gate before real data.** Vitest for clinical logic, Playwright for golden flows, 10 fictional demo patients; the system only goes live with real records after Dr. Ayman approves the tested build.
- **D17 · 2026-11-06 · Git workflow:** feature branches → PR → `main`; phase releases tagged. No `gh` CLI on this machine — plain git over HTTPS.
- **D18 · 2026-11-06 · Compliance baseline from Phase 1:** Egyptian Personal Data Protection Law No. 151/2020 — encryption in transit/at rest, role-based access, audit log, retention/privacy policy, full-database export capability (no vendor lock-in).
- **D19 · 2026-11-06 · Theme palette extracted from the paper files themselves.** The forms are vector PDFs; dominant fills are navy `#17365D`, blue `#1F497D`, steel `#244061`, crimson `#C00000`. These are the Tailwind theme tokens (`--color-clinic-*`), so the digital file literally wears the paper file's colours. Reference images in `knowledge/form-reference/`.
- **D20 · 2026-11-06 · Dev API lives inside the Vite dev server.** A Vite plugin (`server/api.ts` + `server/handler.ts`) serves `/api/*` in the same process as `npm run dev`, so host/port forwarding stays native and there is nothing extra to run. The React app only talks to `src/db/apiClient.ts` — that file is the single seam where Supabase replaces the dev API in production. Dev auth uses scrypt-hashed passwords and `dev-<userId>` tokens; Prisma falls back to `file:./dev.db` when `DATABASE_URL` is unset (prisma CLI commands still need the env var — see README).
- **D21 · 2026-11-06 · Dashboard schema gaps approved and applied (Q11–Q14).** `appointments` (G1), `visits.nextVisitDate` (G2), `diagnoses` (G3), and `location` on visits & episodes (G4) added in migration `phase1_dashboard_fields`; demo data seeded.
- **D22 · 2026-11-06 · DB4 (Prescribing & Practice Analytics) promoted to Phase 2** at Dr. Ayman's request — medication tracking was his own feature request (Q15). Phase 2 dashboards are now DB1 + DB2 + DB4; DB3 and DB5 remain Phase 3.
- **D23 · 2026-11-06 · Dev-server staleness after migrations.** Incident: the long-running preview server (started 16:31) kept a pre-migration Prisma client in its middleware bundle, so `patients/:id` 500'd and the patient page looked blank. Fixes: (a) the API plugin now watches `server/**`, `prisma/schema.prisma`, `prisma/migrations/**`, `prisma/seed.ts` and restarts the dev server on change; (b) the patient page shows a real error card instead of a silent dash; (c) rule — after any migration, restart the preview (or let the watcher do it). Never leave smoke-test dev servers running.
- **D24 · 2026-11-06 · Phase 1 slice 2 entry-grid rules.** (a) Ultrasound milestone payloads are validated server-side against `ULTRASOUND_FIELDS` (src/lib/ultrasound.ts) — unknown keys are dropped, numbers/bools coerced, so the payload can never outgrow the data dictionary (extends D8). (b) Medications are unique on (brandName, activeIngredient, strength); duplicate POST returns 409 and the UI offers the existing row. (c) Prescribing supports inline cataloguing: `POST episodes/:id/prescriptions` accepts either `medicationId` or a `newMedication` object, so Dr. Ayman builds his personal library while prescribing (DB4 groundwork, D22). (d) Delivery/postnatal data is an upsert on `pregnancy_details` (OBS episodes only). (e) Smoke-test lesson: give the dev server an ABSOLUTE `DATABASE_URL` (`file:E:/...`) — a relative `file:./smoke.db` resolves against the process CWD, not the schema dir, and fails with SQLite error 14.
- **D25 · 2026-11-06 · Slice 3 architecture: delegated route modules + dashboards v1 + attachments + print view.** (a) server/handler.ts now delegates to server/attachments.ts and server/dashboards.ts via a shared RouteCtx (server/ctx.ts) — new API areas get their own module instead of growing the monolith. (b) Attachment files store under `uploads/` (gitignored) in dev; rows carry fileName/mimeType/sizeBytes/note; upload = hand-rolled multipart parse (no new deps), 15 MB cap, images + PDF only; download streams with RFC 5987 filename encoding (ASCII fallback + filename* — Arabic names crash Node headers otherwise); `?token=` auth supported for <img>/<a>. Production maps this to Supabase Storage signed URLs at the same seam. (c) Dashboards DB1/DB2/DB4 v1 are read-only aggregate GETs (dashboards/admin, dashboards/clinical, dashboards/prescribing) computed in JS from plain Prisma queries; charts are hand-rolled SVG (no chart library). GA from EDD only (conception = EDD − 280 d); anemia = latest Hb per open-OBS patient, WHO bands, values assumed g/dL until D10 unit normalization ships. (d) Print-to-PDF is a standalone route /patients/:id/print rendering the full file in paper order with bilingual headers; browser "Save as PDF" is the PDF mechanism — no server-side PDF generation.

Same migration batch: clinic logo (public/logo.png) adopted; app chrome switched to a white header with dark navy text (per Ahmed) — logo in header, login, print view, favicon; PWA theme_color now #FFFFFF. - **D29 · 2026-11-06 · Cloudflare Workers Builds is the first live static host; `_redirects` removed.** Ahmed connected the repo to Cloudflare (Git integration). Build succeeded; deploy failed on Cloudflare API error 100324 — Workers static assets reject the Pages-style `public/_redirects` (`/* /index.html 200`) as an infinite loop because SPA fallback is native via `assets.not_found_handling: "single-page-application"`. Fix: `_redirects` deleted, `wrangler.jsonc` committed (name aymanclinic, assets.directory ./dist, SPA handling) so deploys are versioned and deterministic. Netlify loses SPA fallback by this removal — acceptable, not a target. Remaining for data: set `VITE_API_BASE_URL` in the Cloudflare project env once the API is hosted.
